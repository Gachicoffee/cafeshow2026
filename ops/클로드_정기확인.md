# 클로드 정기 확인 — 페이지 메모의 "클로드에게 작업 요청" 처리

정기 실행(루틴)이 이 문서를 그대로 따른다. 사람에게 묻지 않고 끝까지 처리한다.

## 0. 요청 확인 (가장 먼저, 가볍게)
```bash
URL=$(grep -o "https://script.google.com/macros/s/[^']*/exec" app.js | head -1)
curl -sSL --max-time 60 "$URL?action=requests"
```
- `"requests":[]` 이면 **아무것도 하지 말고** "요청 없음" 한 줄로 끝낸다. 파일을 읽거나 저장소를 둘러보지 않는다.
- 연결이 안 되면(403·시간 초과) "웹 앱에 연결하지 못함" 한 줄로 끝낸다. 재시도하지 않는다.

## 1. 요청마다 처리
각 요청은 `row`(메모 탭 줄 번호), `key`(P1·T5·D2·O7 같은 항목), `author`, `text`, 첨부(`fileUrl`)를 가진다.
1. `CLAUDE.md`, `planning/결정사항.md`, `planning/행사정보.md`, `data.js`에서 그 항목(key)을 읽고 맥락을 잡는다.
   - key 앞글자: P=data.js plan, T=tasks(#번호), D=decisions(결정 번호), O=orders(발주 번호).
2. 요청한 일을 한다. 표·계산은 엑셀(.xlsx, Pretendard), 문서는 A4 기준. 숫자는 자료가 있는 것만, 추정은 "추정:"과 근거를 붙인다.
3. 저장소에 남길 것이 있으면 고친다: 결정이 생기면 `planning/결정사항.md`, 의견이 바뀌면 `data.js`의 say·can·help와 `updated`.
   - 공개 저장소다. 금액·거래처 연락처·개인정보는 저장소에 넣지 않고 답장 첨부 파일로만 보낸다.

## 2. 답장 (요청마다 한 번)
- 존댓말, 결론부터, 짧게. 사용자는 "지형님". 커피 용어는 풀어 쓰지 않는다.
- 만든 파일이 있으면 첨부한다(10MB 이하).
```bash
# 글만
curl -sSL --max-time 120 "$URL" --data-urlencode "action=reply" --data-urlencode "row=행번호" --data-urlencode "text=답장 내용"
# 파일 첨부
base64 -w0 결과.xlsx > /tmp/f.b64
curl -sSL --max-time 120 "$URL" --data-urlencode "action=reply" --data-urlencode "row=행번호" --data-urlencode "text=답장 내용" \
  --data-urlencode "name=결과.xlsx" --data-urlencode "mime=application/vnd.openxmlformats-officedocument.spreadsheetml.sheet" --data-urlencode "data@/tmp/f.b64"
```
- 응답이 `ok`면 그 요청은 '완료'가 된다. `ok`가 아니면 그 요청은 건드리지 말고 다음 확인 때 다시 처리되게 둔다.
- `-X POST`는 쓰지 않는다(리디렉트에서 깨진다). `--data-urlencode`만으로 POST가 된다.

## 3. 저장소 반영 (고친 파일이 있을 때만)
1. `git fetch origin main && git checkout -B claude/routine-$(date +%m%d-%H%M) origin/main`
2. 커밋 → 푸시 → `main`으로 PR 생성 → 바로 병합(이 저장소는 대표가 병합을 맡겨 두었다).
3. 답장 끝에 "사이트 반영됨"을 한 줄 덧붙인다.
