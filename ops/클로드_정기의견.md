# 클로드 정기 의견 갱신 (하루 4번)

정기 실행(루틴)이 이 문서를 그대로 따른다. 사람에게 묻지 않고 끝까지 처리한다.

## 1. 새 메모 확인 (가볍게)
시트는 "링크가 있는 사용자 보기"라서 CSV로 바로 읽는다(네트워크 허용 도메인에 `docs.google.com` 필요).
```bash
ID=1k2p3E9k6aNp3Zin-Zr7HOYkKXoKEEIcuhxapFbPHEmU
curl -sSL --max-time 60 "https://docs.google.com/spreadsheets/d/$ID/gviz/tq?tqx=out:csv&headers=0&sheet=%EB%A9%94%EB%AA%A8"          # 메모
curl -sSL --max-time 60 "https://docs.google.com/spreadsheets/d/$ID/gviz/tq?tqx=out:csv&headers=0&sheet=%EB%8C%80%ED%91%9C%20%EA%B2%B0%EC%A0%95%EC%82%AC%ED%95%AD"  # 대표 결정사항
```
- Google Drive 커넥터가 있으면 `read_file_content`로 읽어도 된다.
- 연결이 안 되면(403·시간 초과) "시트에 연결하지 못함" 한 줄로 끝낸다. 재시도하지 않는다.
- `ops/의견_확인기록.json`의 `last`(마지막으로 본 메모 시각 "M/D HH:mm")보다 **새로운 메모**만 고른다. 내용이 `[완료 표시]`·`[완료 취소]`인 줄은 건너뛴다.
- 새 메모가 없으면 "새 메모 없음" 한 줄로 **즉시 끝낸다**. 저장소의 다른 파일은 읽지 않는다.

## 2. 항목별 의견 갱신
메모의 `항목` 값(P1·T5·D2·O7)이 `data.js`의 어느 항목인지 찾는다(P=plan, T=tasks #, D=decisions, O=orders).
- 그 항목의 `brief`를 고친다: `{ done: [확정된 것], check: [확인이 필요한 것], effect: [기대 효과], at: 'M/D HH시 클로드' }`
  - 확정된 것: 메모·결정사항으로 확정된 내용을 짧게.
  - 확인이 필요한 것: 무엇을 누가 확인해야 하는지 구체적으로.
  - 기대 효과: 이 결정으로 얻는 것.
- `say`(한 줄 의견)도 최신 상황에 맞게 고친다. 숫자는 자료에 있는 것만, 추정은 "추정:"과 근거.
- `check`가 비어 있고 모든 내용이 확정된 항목은 **건드리지 않는다**(완전히 확정된 부분은 패스).
- 메모가 새 결정이면 `planning/결정사항.md` 맨 아래에 날짜 제목으로 덧붙인다.
- `data.js`의 `updated`를 오늘 날짜로, `ops/의견_확인기록.json`의 `last`를 이번에 본 가장 최근 메모 시각으로 바꾼다.

## 3. 반영
1. `git fetch origin main && git checkout -B claude/opinion-$(date +%m%d-%H%M) origin/main`
2. `node --check data.js`로 문법 확인 후 커밋 → 푸시 → `main`으로 PR → 바로 병합(대표가 병합을 맡겨 둠).
3. 실행 결과는 "갱신한 항목: …" 한 줄로 남긴다.
